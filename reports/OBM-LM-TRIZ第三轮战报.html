TC-I：NLL 路由精度 vs 推理算力 → No.17 空间维数变化 + No.10 预先作用

物理矛盾：路由必须"全知"（软融合全部细胞才准）且"节俭"（每步跑 1 个细胞才快）。 实测软路由 10.2s/生成 vs 市场 3.4s——精度换来 3 倍算力，不可部署。

解法：把路由决策从"生成期逐步"压缩到"prompt 期一次"——用无填充的真实尾部 64 token 算一次逐细胞 NLL，取 top-1，生成期只跑该细胞。

验证项结果
前缀 NLL(64tok) vs 全窗口 NLL 决策一致率100%（4 域全部窗口）
top1 vs 软路由质量（en_lit / zh / code / wiki）123/121 · 782/782 · 83/87 · 369/369 —— 几乎无损
速度（3 栈对比，40 token 生成）市场 3.40s · 软 NLL 10.16s · top1-prefix 3.27s（比软路由快 3.1×）

路上抓到一个真 bug：初版把左侧 [0] 填充也计入 NLL，pad token 主导打分导致所有 prompt 路由到同一细胞——改为无填充真实尾部后，8 条 prompt 中 7 条命中正确专才（zh/code→cell#3、en 双域→cell#4）。

已部署：demo_sandbox.py --router nll-top1（默认）。端到端验证：def merge_sort 自动路由代码专才，产出 def merge_sort(20) -> None: + docstring 结构，2.5s/次，8GB 沙箱内正常。
