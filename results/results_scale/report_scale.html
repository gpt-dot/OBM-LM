3. 工程注记（诚实记录）

性能：V=16K 下初版 run_step 8.5s/步。三处修复： (a) 路由统计前向融合为单趟（autocast + 分块 softmax/max/argmax 合一， logsumexp 全量物化是单项 1.75s/步的病灶）；(b) decide 的集成统计改在 torch 内计算（旧实现把每个细胞的 (24,256,16384) softmax 搬进 numpy， 1.6s/步）；(c) 熵缓存刷新回归 dist_refresh=10 间隔制（每步强制刷新是 移植期遗留，玩具协议下两种刷新频率决策逐位等价——已对照验证）。 合计 8.5s/步 -> 1.25s/步（6.8×）。
checkpoint：初版三类静默污染——(a) numpy 数组 与活参数共享存储（.numpy()/from_numpy 浅引用），原模型训练经 Adam 就地 更新改写恢复体；(b) cur_x/events/history/segments 浅引用，保存后继续 训练污染快照；(c) 路由统计缓存（上一样本统计）未入库导致恢复体选路 分歧。修复后双引擎（numpy/torch）均实现恢复后逐步位一致（含 pickle 落盘 往返），Adam 一阶/二阶矩与 rng 状态完整入库。
bf16 autocast：CPU AVX512-BF16 下矩阵乘激活值 降精度、参数与 Adam 保持 fp32，实测 1.48× 加速（D=384）。
路由坍缩 bug 与修复（核心发现）：pilot 终局诊断暴露 合同市场坍缩到单一通才细胞 c2——6/6 评估批全选、权重 1.00。code_py 线上 ppl 高达 97861，而 code 专才 c1 的单细胞 ppl 仅 1332（73× 差距）； en_wiki 48850 vs 专才 3401。三大病灶：(a) 未训练段的 cond_reliability 先验 0.5 让「从未受训」≈「专才」；(b) 合同池空 时回退到陈旧 probe 缓存（上次训练批）做彩票授予，eval/生成路径 张冠李戴；(c) 难域绝对精度达不到记账线 0.12，专才 seg_rel 磨到 0 过不了 合同线。修复：未知段先验改 0（未证明=不可靠）、探针彩票门禁到训练路径 （eval/generate 改按 cond_rel 排序取 top-k）、引入段内峰值参考。 零重训练、纯换选路逻辑：code_py 97861→1141（86×↓）、en_wiki 48850→3842（13×↓），routed 与单细胞最优对齐；en_lit/zh 路由到其天然归属 细胞 c2（owner 不变，集成轻微稀释）。详见各 run 的「路由诊断」表。 experiments/diag_routing.py 复现该诊断。
玩具回归守卫：experiments/toy_regress.py （numpy 路，6 段 × 300 步）在每次改动后必跑——终局精度、封存/分裂/凋亡/ 复现授予事件数、复现段抗遗忘三条底线。experiments/torch_smoke.py 覆盖 torch 路全机制（梦境/评估/checkpoint/生成）。
